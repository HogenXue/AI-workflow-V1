# Official OpenAI guidance

Fetched 2026-10-05 via official-site search, then opened the full relevant sections. No direct official Docs MCP is exposed; official-domain web search/retrieval was used. Older Codex URLs redirect to OpenAI's ChatGPT Learn documentation.

- [AGENTS.md discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md): global home guidance loads before project root-to-working-directory guidance; one non-empty applicable file per directory, with `AGENTS.override.md` before `AGENTS.md` and configured project fallback names. Nearer guidance comes later. The default project-document budget is finite; keep guidance small. Repository template names are not automatically runtime instruction files.
- [Skills](https://learn.chatgpt.com/docs/build-skills): metadata drives implicit matching; full bodies load progressively. Repo/user skills use `.agents/skills` scopes. Same-name skills are not merged and can both appear; narrow trigger descriptions and avoid duplicate installations. Preserve explicit-only policies where established. Plugins are suggested for broader distribution, but this task keeps the user's existing local installer.
- [Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra): keep descriptions precise and short, disclose detailed guidance only when needed, remove redundant always-read/always-test instructions, and preserve concrete decision boundaries. Do not turn a trivial edit into a full workflow.
- [Skill evaluations](https://developers.openai.com/blog/eval-skills): test direct requests, natural task matches, realistic context and nearby requests that should not activate a skill. Inspect behavior, not only final prose. Small targeted cases are useful; they do not prove every future model outcome.

Application: correct template authority claims, retain native Trellis ownership, condense duplicate generic rules, make task documents facts/acceptance rather than a new prompt privilege layer, and refine overlapping descriptions. System/developer instructions and real tool permissions are never overridden by repository guidance or skills. No installation/configuration/model/API changes are authorized merely by these pages.
