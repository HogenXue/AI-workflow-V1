# Research

Adapted from Matt Pocock's AIHero skills. Define the question and decision it supports before gathering evidence. Read existing notes first; distinguish unresolved research from already verified facts.

Follow each material claim to official documentation, source code, specifications, papers, or first-party APIs. Check dates/versions when they affect applicability. Cite sources beside findings; identify conflicting evidence, assumptions, and unknowns rather than turning guesses into facts.

Work inline by default. Use a background researcher only when the project's host dispatch mode and user/task authorization permit it; pass the active task and exact question, avoiding duplicate work. Missing delegation capability does not prevent source research.

Persist concise findings in the established research location. In Trellis use `<current-task>/research/<topic>.md`, with the question, findings/evidence, implications, limits, and follow-up evidence required. Add native context references when needed. Outside Trellis follow existing notes conventions or the user's chosen destination.

Research authorizes reading and the requested notes, not implementation, provisioning, external publication, Git operations, or automatic changes to task state. Return evidence to native planning.
