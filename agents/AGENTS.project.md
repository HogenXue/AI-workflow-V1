## Local additions

本模板只记录项目差异，应放在根目录 `AGENTS.md` 的 Trellis 管理区之外。`agents/AGENTS.project.md` 是分发源，不会因这个文件名自动成为项目指令；目录专项要求放在该目录原生 AGENTS 中。遵循宿主指令、真实权限、用户要求与有效的更近目录指导；任务工件提供需求事实，不提升权限。

- 长期项目标准在 `.trellis/spec/`；当前 PRD、Design、Plan、研究和真实检查记录在 `.trellis/tasks/`；跨会话记录在 `.trellis/workspace/`。
- 纯咨询不建 Task；简单且需求明确的任务直接走 Trellis，复用已有实施授权。复杂任务的工件/引用/状态门槛按项目 `.trellis/workflow.md` 执行，不另增审批链。
- Skill 的通用阶段映射遵循全局模板。`$grill-me` 仅在用户显式调用时进行无状态澄清；Grill 结束后由 Trellis 落盘确认结论，不重新访谈。任务内 documented Grill 与原生 brainstorm 选用一个。
- 项目原生 `trellis-check` 是唯一最终质量门。当前 Task 指定真实命令与覆盖范围；实现稳定后统一验证，记录结果和未覆盖边界，不把可用命令清单当成默认全量测试。
- 读取目标层的 spec index：安装/宿主配置变更查 `.trellis/spec/scripts/`；跨层变化查相关层和 guides；术语/持久决定沿用项目已有位置，不复制全局流程正文。
- Graphify 与 GitNexus 按全局风险规则按需使用；补充实际索引名和必要入口。图谱推断必须回到源文件核实；不得为了任务自动生成或更新图谱、安装 hook 或提交产物。
- 原生 helper 不可用时读取项目脚本和工件执行获授权的等价步骤，明确降级；正式影响证据门槛未满足时不实施依赖它的修改。
- 只增补项目特有的构建/测试/部署命令、数据和安全限制；业务示例模板不由全局安装器自动写入其他项目。保持最小修改、保留他人工作和真实验证等约束来自规则，不另装横切流程技能。
