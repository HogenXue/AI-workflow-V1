# AI 工作原则（Trellis 兼容全局模板）

## 1. 作用域与指令来源

本文件是仓库中的分发模板；安装为宿主全局指导后生效。`agents/AGENTS.global.md` 本身不是 Codex 自动发现的项目指令文件。

所有 AGENTS、Skill 和任务工件都服从宿主系统/开发者指令、真实权限边界及用户明确要求，不能自行扩大授权。PRD/Design 是需求与验收的事实来源，不是新的指令权限层；冲突时依有效项目规则澄清，不把旧任务内容当作最新用户决定。

Codex 全局 home 优先选非空 `AGENTS.override.md`，否则选 `AGENTS.md`。项目从根到当前目录逐层选择 override、普通 AGENTS 或已配置的项目 fallback 文件，每目录最多一个；更近目录的指导覆盖较早的同类指导。不要假定同目录 override 会与普通 AGENTS 一起加载，也不要擅自删除 override 或改配置。其他宿主遵循其原生发现机制。

全局指导定义通用默认，项目/子目录只补充适用的构建、领域、风险和验证要求。保持简短，按任务读取相关规格，避免把全部技能正文或全仓文档塞入 AGENTS。[官方发现机制](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 2. 工作约定

- 默认使用中文回复；事实、实际动作、验证结果与推断分开说明。
- 只修改完成当前任务必要的内容；保留用户已有修改，不覆盖或回滚无关工作。
- 明确的实施请求授权该范围内的规划记录、实现和必要验证，复用已有授权；只读排查/审查不授权修复。仅对未决业务、范围扩大或高风险决定询问。
- 按任务需要读取代码、规格和工具，不为每次小改固定读整仓或加载一套技能；Skill、MCP 和 Agent 用于解决实际需要。
- 工具不可用时说明限制并执行获授权的原生等价步骤；不虚报工具/测试结果。依赖正式影响证据的修改仍须满足项目门槛。

## 3. Trellis 与能力路由

存在 `.trellis/` 时，Trellis 是任务、规格和状态的唯一工作流来源。先确认匹配本次需求的会话 Task、状态和必要工件；纯咨询不建 Task。没有专用工具不等于跳过 Trellis：优先原生命令/Skill，未暴露时读取 `.trellis/workflow.md` 和本地脚本执行等价步骤。

简单且明确的请求进入 Trellis 轻量流程，PRD 足够时不强行增加设计/计划，不自动启动复杂规划或全仓验证。复杂工作按原生要求完善 PRD、Design、Plan 与上下文引用；使用项目原生 `task.py validate <任务目录>` 校验引用，原生 start 门槛满足后才实施。PRD、Design、Plan 分别记录需求、方案和执行，不创建第二套工件或状态机。

| 当前目标 | 主能力入口 | 归属与排重 |
| --- | --- | --- |
| 文档化未决需求 | 自动选用 `grill-with-docs`，不可用时用原生 `trellis-brainstorm` | 复用当前访谈入口与已确认结论；当前 PRD/Design/Plan，`grilling` 只辅助提问 |
| 综合已确认需求 | `to-spec` | 当前 PRD；不重新访谈或发布第二份规格 |
| 拆分已定交付 | `to-tickets` | 原生父子任务、真实阻塞与解除证据 |
| 大型工作先梳理决定 | `wayfinder` | 当前 Design 的前置决定地图；不是第二套任务状态 |
| 查外部事实/专题证据 | `research` | 当前 `research/`；普通源码定位不自动启动研究流程 |
| 试验一个设计问题 | `prototype` | 有界可丢弃演示；不自动转成生产实现 |
| 实施已批准工作 | `implement` + 按风险使用 `tdd` | 原生执行、规格加载、inline/dispatch 规则 |
| 审查当前改动 | `code-review` | Spec/Standards 分析融入同一次原生 `trellis-check` |
| 交接会话 | `handoff` | 当前 Task/Journal 与已有工件指针，不自动恢复工作 |
| 专项诊断/设计/冲突 | `diagnosing-bugs` / `codebase-design` / `resolving-merge-conflicts` | 服务当前任务；诊断/设计本身不授权修复、重构或 Git |

自动文档化澄清：在获授权的任务规划中，先读当前工件、相关规格和代码；仍存在影响范围、关键方案或验收且需要用户决定的问题时，自动选用上述访谈入口，无需用户点名。事实问题先查证，普通实现细节自行判断，明确需求直接继续。实施中发现需求缺口时回到原生规划，只重开受新证据或需求变化影响的问题；确认后写回当前工件并按原生门槛继续。

`$grill-me` 仅在用户显式调用时使用。该显式 Grill 期间只进行无状态对话，不写文件、不修改 Task、不实施；确认后交回 Trellis 持久化，不再启动相同的 documented Grill/brainstorm。任务复杂本身不要求访谈；只问查证后仍需用户决定的前置条件已满足的问题。

领域术语由 `domain-modeling` 在既有领域位置澄清；软件模块接口设计由 `codebase-design` 提供方法。稳定且有真实取舍的持久决定写既有决策位置，任务专属方案留在 Design。批量建子任务保留父任务路径，用原生支持的 `create --parent ... --no-start` 保持规划关联；不要仅为恢复指针调用 `start` 而提前进入实施。

Skill 不得创建与 Trellis 平行的任务生命周期。每个动作选择一个主能力，需要时使用互补方法；`implement` 不再启动第二个实施 Agent，`code-review` 不再启动第二套检查。不运行未适配的上游 setup、`.scratch` 工单、自动 tracker 发布或自动提交指令。

项目没有 `.trellis/` 时遵循已有工作流和文档位置，不仅为使用技能自动初始化 Trellis 或增加任务系统。

## 4. Skill 发现与职责边界

- 用户点名时使用其所选且可用的技能；自动选择按具体目标与描述匹配，只读取所选技能及需要的引用。技能不作为每次修改都必须单独执行的工作流阶段。
- 描述写清实际触发条件和相邻请求的边界；发现、综合、拆分、实施与审查是不同目标，不按关键词强行串联所有技能。
- 已有确认答案或有效检查证据直接复用；同时处理多个目标可以使用互补技能，但不重复同一动作。
- 同名 Skill 不会自动合并，不能推断“项目同名必然覆盖全局同名”。显式确认当前来源并保留一个获选副本；未经授权不删除其他技能、不改变 invocation policy。[官方 Skills 指导](https://learn.chatgpt.com/docs/build-skills)
- `grilling` 辅助已启动的访谈，`domain-modeling` 澄清领域语言；二者不另开采访或任务。研究不替代 Bug 复现，原型不替代生产实现，交接不授予实施或 Git 权限。
- Graphify：已有可用图谱时按需理解关系；简单源码定位或局部修改不要求使用。不得为了任务自动生成/更新图谱、安装 hook 或提交图谱产物。
- GitNexus：公共接口/数据契约、跨模块高影响、删除迁移或陌生高风险调用链按项目规则分析；局部低风险修改不自动调用。HIGH/CRITICAL 先报告，图谱结论回到源文件核实。

## 5. 验证与协作

最终验证是**任务级门禁**。选择能覆盖实际风险的最小检查：文档做文件/结构检查，局部行为做相关测试，跨模块或公共契约补足必要集成/迁移证据。TDD 适合需自动化证据的行为变化，不给纯文案或配置制造 RED。

当前 Task 写明所选检查和覆盖范围；可用命令清单不是默认必跑清单。实现稳定后完成原生 `trellis-check` 并在任务内记录真实命令、结果与未覆盖边界。确认使用临时 fixture 且无真实环境访问的本地检查，可在已授权范围内运行、修复任务引入的问题并针对性复验，不逐步重复申请同一授权。

失败时集中修复任务相关问题，重跑受影响检查；无关基线失败单独记录，不顺手修复或放宽断言。相同成功检查只在覆盖内容、依赖、配置、工具链或环境实质改变而失效时重跑；仅 HEAD、commit 数量或 Task/Journal 变化不自动触发全套复测。CI 使用自身配置的检查，不依赖活动任务。

只有用户或适用项目/技能流程明确允许时委派；遵循宿主 inline/dispatch 模式。传入真实当前任务和范围，不创建独立的并行工作流。子代理做分配范围的针对性检查，主代理汇总并执行最终门禁；不得重复全量验证或借委派扩大授权。

## 6. 记忆、Git 与宿主配置

Recallium/Mem0/Memory 提供长期上下文，不替代 PRD、Design、Task 或 Journal。项目要求 Recallium 时，会话开始调用 `get_rules`，修改前/历史问题调用 `search_memories`；实现验证后 `store_memory` 保存稳定决定、经验和真实验证状态，并关联 `related_files`。后端不可用时说明，不虚报检索/保存；完成说明报告记忆是否保存，未保存时建议恢复后保存。Codex 宿主 memories 与外部后端分别按实际可用能力使用。

未获对应明确授权，不执行 commit、push、merge/rebase、PR 发布、分支删除或其他破坏性 Git 操作。检查通过或任务验收完成不自动授予 Git/归档授权；保留无关 dirty work。归档前依原生任务验收和有效证据收口。

不自动修改真实全局 `config.toml`、MCP、插件、hooks、权限或模型设置；只执行当前授权的增量变化。本包维护源在 `agents/` 与 `skills/`，经明确安装才同步宿主；不直接编辑真实用户级 `.codex/AGENTS.md`。不得声称未运行的安装、测试、工具或 Git 动作已完成。
